## IN: submitted reports and bounded review

Architecture §10.6 resolves PB-A9/AB-A10: `submitted` is the sole report status. A review note and reviewer/time/revision describe an annotation, never approval, rejection, attestation, payable time or a billing prerequisite. New scheduling capabilities are technical operation names: `TimeReports.ReportOwn` for tenant_admin/projektledare/montor and `TimeReports.Review` for tenant_admin/projektledare. Role union remains authoritative; seller/economy/platform identity alone grants neither. Review covers the current tenant including standalone reports with no job, consistent with current manager `Jobs.ViewAll`. It does not grant on-behalf filing or rewrite another reporter's fields. Arbetsledare is not a tenant role or time-review escalation in this story.

Store one `time_reports` row per deliberate filing: tenant, actor user, ISO calendar report date, positive whole-minute duration fitting PostgreSQL integer, optional booking/job IDs, optional reporter note, SQL creation time, submitted status. A standalone report needs no person profile. A linked booking requires a nonarchived reporter profile attached to the actor's current active membership, current planned booking assignment and same tenant. The existing Montör-specific `booking_owned_by_current_user` cannot alone authorize PL/Admin filing. Derive the linked job from the locked booking; reject an explicit mismatching job, including attempting to add a job to a booking with no job. Without a booking, an optional job must pass existing current `job_can_read`. No job/quote status means time approval; accepted quote/job source references and booking conflict acceptance remain untouched.

Duration-only hours entry converts locale decimal dot/comma to exact integer minutes and rejects fractional minutes/nonfinite/zero/negative/overflow values. Start/end entry is an alternative convenience using actual instants and the existing Stockholm conversion policy, not naive wall-clock subtraction; its local start date defaults the report date. Booking prefill uses full real booking instants/job association and can be adjusted. Do not impose an invented eight-hour day, salary percentage, billing rate or business maximum; integer storage supplies the technical bound. Filing is a declaration, not proof that reported hours occurred inside the booked interval. Multiple legitimate rows per user/date/booking remain possible; retry identity prevents accidental duplicates, not a uniqueness rule on business dimensions. Reporter/reviewer notes are trimmed nullable strings with a shared 2,000-character limit enforced by UI, command and SQL; blank annotation deliberately clears the current note and still records actor/time/revision.

Capture nullable `booked_minutes_at_filing` inside the filing transaction for a linked booking. It is nonmonetary provenance supporting the required review delta after booking changes/reassignment. The review sheet labels comparison as this report's minutes minus booked minutes **at filing**; a standalone row shows no booked comparison, never zero fabricated from missing/inaccessible data. Personal week totals group submitted minutes by report date. Missing indicators use weekdays with planned own booking overlap in the local date but no submitted row that date; they are nudges, not validation. Job/person sums count each report once and include a clearly labelled unlinked group. A day nudge is suppressed by any submitted own report on that date; it does not claim hours are complete.

## IN: authority, persistence and retry

New table: direct tenant_id; composite same-tenant booking/job FKs; actor user FK; ENABLE + FORCE RLS; explicit safe public SELECT columns under active membership ∧ capability ∧ (own user or reviewer). Private filing/review request digests/results are excluded by column ACL and all projections. No anonymous access or authenticated direct INSERT/UPDATE/DELETE. Checked authenticated RPCs own filing and annotation; their SQL authorization is independent of the TS envelope. Empty search_path, schema-qualified references, revoked PUBLIC/anon defaults, narrow grants and negative tests are mandatory. Enroll the table in the manifest, exhaustive H4 inventory and exact policy/ACL harness.

Use existing tenant-row serialization and current membership/role lock ordering. Filing authorizes current actor before replay lookup, then exact actor+attempt UUID/normalized request digest returns the existing own report without duplicate audit; changed content under a token rejects. Fresh filing rechecks/locks assignment, booking and optional job before one report+append-only audit commit. Exact replay of an already filed own report does not require a still-existing assignment; it returns the frozen original report, not new reference data. Revoked membership/capability still denies replay. An uncertain response retains exact payload/token and input for explicit retry; editing after uncertainty must first reconcile that attempt. A definite failure permits correction/new attempt. No offline queue or automatic resend.

After filing, report identity/date/duration/reporter-note/links/snapshot/status/attempt fields are not mutable through this story. This adds no self-correction, delete, archive or retention workflow. Annotation is a dedicated reviewer command with expected review revision, one current bounded review note, server reviewer/time, atomic audit and the latest review attempt/digest. Identical latest retry is idempotent; a superseded attempt returns a stale result requiring refresh, never overwrites a newer annotation or falsely claims its old note remains current. DB update allow-list/trigger rejects all core-field mutation, and normal callers lack raw update grants. Review affordance opens the sheet and saves annotations; no hard state is added.

## IN: E13 missing-day nudges

Owner-authorized default: hourly UTC `0 * * * *`, previous seven completed tenant-local dates, Monday–Friday only. Eligible recipients are active current reporting-capable memberships with a nonarchived own profile and a planned own booking overlapping the day, with no submitted own row for that date. Do not nudge today/future, infer paid schedules or absence obligations, or widen the recipient roles. Category `time_report.nudge`: in_app only, enabled by default, nonessential/disableable; fixed Swedish content and fixed `/time-reports` deep link (no URL query). Logical subject=user UUID, logical period=missing local date; existing unique notification identity prevents duplicates across hourly/retry/concurrent runs. An already inserted reminder remains historical after later filing; this is not a live missing-time count.

Existing booking tables revoke service_role table access. Do not copy the quote producer's raw scans or widen raw grants. Add a service_role-only checked DEFINER RPC that explicitly pages tenants/current eligible users and computes/inserts a bounded page of reminders under current membership/preference/report checks. Each newly emitted reminder and sanitized system audit (actor NULL, producer command, targetId only) commit atomically; duplicate emits add neither notification nor audit. Return only continuation and count metadata, not personal/booking/report facts. Freeze the as-of/window across pages; validate continuation scope, use stable keyset order and bounded pages (at most 25 recipients × 7 dates); coordinate filing/nudge predicate checks through existing tenant serialization so a completed filing before the nudge check suppresses the reminder. The existing authenticated runner owns claims, bounded continuation, run-log/system audit and failure visibility. No new endpoint/scheduler/runtime, service identity in client/read/filing paths, email template, provider activation or sending-control change. Preserve booking.changed category/channel and emitter.
