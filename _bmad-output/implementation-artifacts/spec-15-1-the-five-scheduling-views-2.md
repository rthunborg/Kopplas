## Intent

**Problem:** Resource bookings and the responsive editor exist, but planners lack the five approved live scheduling projections and actual calendar entry hosts. Deactivated assignees can remain attached to unarchived profiles/bookings; Projektledare cannot directly read peer membership status, so the required needs-reassignment lane needs a narrow authoritative disclosure.

**Approach:** Activate Planering at `/scheduling` with one authorized booking/filter model, shared toolbar and five role-appropriate projections. Reuse the existing editor for creation and proposed move/resize changes, and add one checked, read-only lifecycle RPC returning only a booking ID and derived needs-reassignment boolean; the server remains the sole persistence and conflict authority.

## I/O & Edge-Case Matrix

| State/input | Expected behavior | Failure handling |
| --- | --- | --- |
| Booking overlaps half-open selected period | Include if start < period end and end > period start; clip displayed blocks at period/day edges but preserve exact editor instants | Reject nonpositive/invalid intervals generically |
| Person/booking arbetsroll/job/customer filters | AND across categories; common eligible set across projections; personal agenda additionally intersects authenticated self assignment | Restore unavailable values to valid defaults visibly |
| Multi-assignee, disabled/ended/reactivated member or archived profile | Same ID can occupy several resource rows; count uniquely elsewhere; planned affected bookings appear in reassignment lane for selected period | Only authoritative RPC boolean drives lifecycle marker/lane; unavailable flag never defaults false |
| Zero/negative effective capacity budget | Numeric demand/balance and explicit no-capacity text; positive demand at zero budget overbooks and drills to bookings; no NaN/Infinity | Missing/incomplete facts show unavailable/retry, never 0% |
| Failed later page or lifecycle batch | Publish no partial/stale list, false empty state or fabricated zero conflict/capacity/reassignment count | Generic Swedish failure/retry; retain toolbar state |
| Actual click/drag/reverse drag/cancel | Positive normalized selected interval/person enters existing editor; cancel writes nothing and restores focus | Invalid selection cannot submit |
| Corrupt/denied storage or actor/tenant switch | Versioned user+tenant+view toolbar preferences only; safe defaults | No bookings/editor drafts stored by this feature; storage failure does not block connected reads |

## Design Notes

### Exact lifecycle RPC contract

Signature: `public.booking_reassignment_flags(p_tenant_id uuid, p_booking_ids uuid[]) RETURNS jsonb LANGUAGE plpgsql STABLE SECURITY DEFINER SET search_path = ''`. Authority derives only from `auth.uid()`, no actor/correlation/proof. Static SQL, fully schema-qualified application/auth references, no locks/writes/audit/events/outcomes/detector facts/clock filtering.

Before shape checks, require nonnull auth.uid/tenant and BOTH `public.has_tenant_role(p_tenant_id, ARRAY['tenant_admin','projektledare']::text[])` AND current Bookings.View set `public.has_tenant_role(p_tenant_id, ARRAY['tenant_admin','projektledare','montor']::text[])`. Helper reads current active scalar+secondary roles; unchanged JWT retains no revoked stored authority. Second check records the current view boundary; source has no additional SQL capability table/checker or deny flags. Match existing manager booking SELECT: existing requested booking ID with matching tenant, without extra job/customer/lifecycle requirements.

Accept one-dimensional array of 1–50 DISTINCT nonnull UUIDs (current `RLS_ID_BATCH_SIZE`). After authorization, check RAW `pg_catalog.cardinality(p_booking_ids)` is 1–50 before any unnest/deduplication/target joins; the bound applies to total supplied elements, not only distinct count. Then reject null elements and duplicates. Null/empty/multidimensional/duplicate/oversized input raises `23514`, literal `booking input invalid`. UUID transport-format failure is not a target-existence distinction. Missing auth/null or foreign tenant/inactive or unentitled caller/ANY missing or foreign booking raises identical `42501`, literal `booking denied`; whole mixed batch rejected without partial output/missing-ID details. App exposes no raw SQL/transport contents: explicit `42501` generic denied, `23514` generic invalid input, other I/O/shape/completeness failure generic retryable error. A collected booking disappearing before its batch fails whole read/offers reload or retry without existence-specific message.

Return JSON ARRAY in request order, one exact two-key object per booking: `[{"bookingId":"<uuid>","needsReassignment":true}]`. Build from `public.bookings` joined to `pg_catalog.unnest(p_booking_ids) WITH ORDINALITY`; final array length must equal cardinality or generic booking denial. For each verified booking flag is EXISTS over matching `public.booking_assignees`, LEFT JOIN same-tenant `public.person_profiles` on profile ID/tenant, LEFT JOIN same-tenant `public.tenant_memberships` on profile membership ID/tenant: true iff profile missing OR profile.archived_at IS NOT NULL OR membership missing OR membership.status IS DISTINCT FROM 'active'. OR across all current assignees; healthy false, disable/end true, reactivate false unless another assignee/profile still requires reassignment. Current status is TEXT `invited|expired|revoked|active|disabled|ended` (20260910165124 migration:18); no new enum. Valid composite FKs prevent ordinary missing-profile/member fixtures; retain fail-closed LEFT joins but never drop constraints to manufacture impossible integration records. No flag widening to work-role/percentage/absence/conflict reasons or picker absence.

Exact ACL: `REVOKE ALL ON FUNCTION public.booking_reassignment_flags(uuid,uuid[]) FROM PUBLIC, anon, authenticated, service_role; GRANT EXECUTE ON FUNCTION public.booking_reassignment_flags(uuid,uuid[]) TO authenticated;`. Controlled migration owner retained; no public/anon privileged path/table grant. This is honestly NEW authenticated EXECUTE while tenant-role capability/table SELECT entitlements remain unchanged.

Server collects all authorized booking pages, skips RPC on empty set, batches max 50 IDs, requires exact length/order, exactly two keys, requested unique UUIDs and boolean values. Reject missing/extra/duplicate/truncated/malformed/unknown-key/failed results, never `?? false`; publish only after all facts/batches validate. Own-only never calls or emits bit (absent+listed). JSON array avoids set-return truncation. STABLE statement snapshot is read-only; deterministic multi-request paging is not a frozen global concurrent-write snapshot. Fresh reads after save/lifecycle changes use current authority/facts; failures explicit.
