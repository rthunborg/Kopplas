## Source constraint and selected smallest proposal

`SchedulingViewsHarness.signIn` clears cookies, navigates to `/login`, submits the real form and waits for `/dashboard`. It does not wait for scheduling request completion. The current AC2 response/failure listeners are installed only after `await h.signIn("montor")`. A scheduling request may therefore already have started before those listeners exist, even though its Response arrives later and is admitted normally. `drain()` checks only captures registered at Response time; zero captures does not mean zero started flights.

Add a test-local, public request-lifecycle tracker immediately after the existing manager-view assertions and **before calling Montör sign-in**. At that point `page.url()` supplies the established application origin. Install the three owned `request`, `requestfinished` and `requestfailed` listeners synchronously, without an intervening await, before the sign-in action can generate dashboard scheduling prefetches. Keep the existing response collector disabled until sign-in returns, exactly as today; do not capture or assert manager/login payloads as Montör payloads. This needs only the AC2 callback in the existing scheduling browser file, not a harness/fixture/app change.

The tracker uses the actual public Request object as its identity. Its matching predicate is the established origin and pathname `/scheduling`, on this Page; no method, query, resource type, prefetch/header, navigation, person, tenant or content-type exclusion is allowed. It neither changes requests nor supplies responses. Store only live objects in an attempt-local `Set<Request>` plus a safe generation counter and a wake notification. No retained request history, URL list, header list, session/tenant identifier or new diagnostic output is introduced. Captured-request ordinals and capture settlement counts remain the existing observer's counters; tracker objects must not be counted as fulfilled captures.

On matching `request`, synchronously register the object, increment generation and wake any waiter. `requestfinished` removes only that exact live object and wakes; successful network termination is not permission to bypass its admitted `finished()`/`text()` capture. A successful HTTP transport with non-OK status remains outside the unchanged OK response collector; the lifecycle tracker does not create an alternative status/body assertion.

Before the Montör capture window opens, the tracker only maintains lifecycle bookkeeping. A request that finishes/fails before that existing window is not retroactively admitted as a payload capture. This preserves the original session window, rather than manufacturing earlier coverage. Once the window opens, every admitted response is still captured, including a Response whose Request was already live at sign-in completion. No terminal failure of an admitted Request is discarded or treated as a successful flight.

For a tracked live Request failing while the Montör window is open, fail the navigation barrier even if no successful Response has yet been admitted. Obtain the public native string using the already validated `Request.failure().errorText` rule, including an empty string; absent/throwing metadata uses the same fixed unavailable Error. Record through the existing boolean first-error sentinel and wake the barrier. If that Request is already admitted, preserve the original failed-capture snapshot path and its exact 20-key privacy/size limits. An unadmitted failed Request produces no invented failed-capture snapshot and no fake Response/status/body/counter. This stricter pre-response barrier failure path is the explicit observability-contract delta requiring independent validation; it cannot be represented as an existing passing-body repair.

## Native barrier and action sequencing

Wrap the existing first tampered `page.goto` invocation in a local `navigateAfterBarrier(action)` operation. Preserve the original URL, native `goto` options/defaults, subsequent `h.settle()`, native response reads, and every assertion. The operation must:

1. Throw the existing first failure immediately if already recorded, including any falsy value.
2. Wait for all currently live matching Requests to reach native terminal events, racing the existing failure signal. The waiter must be registered before its live-set/generation recheck, preventing a terminal event between the check and waiter registration from being lost. It must also wake on new requests; a snapshot of the initial Set is insufficient.
3. Drain every admitted native capture with the existing failure-aware drain, including newly admitted Responses while flights settle. Terminal request events alone cannot substitute for `await response.finished()` and `await response.text()`.
4. Recheck failure, live-set emptiness and request generation after each asynchronous wait/drain. If a new flight/capture arrived, repeat without calling the action. Do not use an idle delay, timeout increase or a status-based exception to force progress. Existing test timeout remains the bound on a permanently live flight.
5. On the final synchronous turn, verify no live flight and no undrained capture remains, then **invoke** the original action in that same turn before another await. Do not return a resolved barrier and have the caller call `goto` later; that adds an avoidable host-side gap. Await the returned native action promise normally and route any original action error to the unchanged first-failure mechanism.

The same local operation may guard the existing date fill, with the original fill arguments, so it cannot intentionally overtake an observed flight. It must not replace the action, add an event listener that rewrites transport, or change assertion order. After the action, retain `h.settle(); await drain()` and all existing assertions. At successful closure, detach only the owned response listener and keep lifecycle/failure listeners installed throughout the final full drain and terminal-flight check; remove only these owned listeners in finally. No later failure, metadata getter or cleanup error can replace the first observed value.
