### A. Encrypted private-memory comparison bridge

Ciphertext is a transport envelope, never a successful receipt field or replacement identity key.

1. Host generates a fresh non-exportable P-256 ECDH private key per attempt. Only its validated 65-byte uncompressed public point is embedded in the constant bootstrap. Each document generates its own non-exportable P-256 key; the document public point is sent by the dedicated binding. Validate curve/point encoding/import, exact lengths and version before deriving; failure freezes that document UNKNOWN with a fixed enum, never the underlying exception.
2. Each side derives the shared ECDH secret, then HKDF-SHA256 derives separate browser-to-host and host-to-browser AES-256-GCM keys. Drop derivation byte buffers after key import. New public points/salt are cryptographic bootstrap material, not fixture/application identifiers.
3. Each direction uses its distinct key and a 12-byte IV consisting of a fresh four-byte direction prefix plus an eight-byte monotonically increasing sequence. Sequence starts at zero, never repeats, and cannot wrap. Authenticate version, message type, bounded document ordinal, direction, sequence, length and both public points as AAD. Strict increasing sequence, one-use state and document ownership reject replay, reordering, cross-document and cross-attempt substitution. No plaintext fallback, retry with reused IV or logging of decrypt/parse errors.
4. Serialize plaintext as strict UTF-8 JSON with fixed tuple/field schema and fatal decoding. Reject extra fields, non-safe integers, malformed base64, invalid tag, unknown type, wrong sequence, invalid point and oversized input before allocating/decrypting where possible. Pad authenticated plaintext to fixed 131,072-byte records (length prefix plus zero padding); each encrypted record is at most 131,088 bytes before base64. No compression. At most 16 documents, 8 envelopes per document and 32 envelopes per attempt; each side has at most 2MiB transient bridge storage. Exceeding any limit makes affected correspondence/redaction UNKNOWN, never increases a limit or changes application reads.

Host associates a browser row with the original public Request reference and unchanged native capture ordinal only after the closed complete bijection succeeds.
