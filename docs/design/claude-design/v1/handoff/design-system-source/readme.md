# Kopplas — Design System

> **Working name.** The brief offered three candidates: **ELPRO**, **VERKA**, **KOPPLA / KOPPLAS**. The system is built as **Kopplas** (from *koppla* — "to connect / to wire up") because it names what the product does: it binds the phases of electrical work into one chain. Renaming is a find-and-replace of the wordmark; nothing structural depends on it. The internal component namespace still reads `KopplaDesignSystem_*` — that string is generated by the tooling from the project folder name and is not user-visible.

## What the product is

Kopplas is a **verksamhetssystem** (business operations system) for electrical contractors. It connects the whole chain of work in one place:

1. **Prospektering** — leads, site visits, quotes (anbud).
2. **Projektering** — planning, drawings, materials, crew and time budget.
3. **Genomförande** — work orders, time reporting, deviations (avvikelser), ÄTA.
4. **Dokumentering** — egenkontroll, test protocols, as-built docs, handover.
5. **Fakturering** — invoicing on fixed price, running account (löpande räkning), or ROT.

Alongside that chain sits **asset and maintenance oversight**: the company's vehicles, tools, instruments (with calibration dates), and recurring maintenance planning.

**Who uses it:** owner/managers of 5–150-person electrical firms, project managers (projektledare), and electricians in the field on phones. The office user gets density; the field user gets big touch targets and short paths.

**Language:** the product ships in Swedish. UI copy, labels and sample data in this system are Swedish; documentation (this file, prompt files) is English.

## Content fundamentals

**Voice: a competent colleague, not a vendor.** Short declaratives. The system states facts and next actions; it does not cheer. Nothing is "amazing", nothing is "seamless".

**Casing.** Sentence case everywhere — buttons, headings, table headers, menu items, empty states. ALL-CAPS is used only for micro-labels (eyebrow labels, table group headers) at 11–12px with `--track-caps`. Never Title Case.

**Person.** Address the user as **du** ("Du har 3 avvikelser att granska"). The system refers to itself in the third person only when unavoidable ("Kopplas skickar påminnelsen automatiskt"). Never "vi" for the software. Possessives are dropped where Swedish allows it: "Projekt", not "Dina projekt".

**Verbs first in actions.** `Skapa anbud`, `Rapportera tid`, `Attestera`, `Skicka faktura`. One word if one word suffices: `Spara`, `Avbryt`, `Klart`.

**Numbers carry the message.** Figures are the loudest thing in a card; the label above them is quiet. Currency: `284 500 kr` (space as thousands separator, lowercase `kr`, never `SEK` in UI). Percent: `84 %` (space, Swedish convention). Dates: `12 mars`, `12 mars 2026` when the year is ambiguous, `2026-03-12` in tables and file names. Time spans: `4 h 30 min`. Never "approx." — give the number or say `Ej beräknat`.

**Empty and error states name the next step.**
- Empty: `Inga avvikelser. Bra jobbat.` / `Inget rapporterat den här veckan.` + a single action.
- Error: what happened, then what to do. `Kunde inte spara. Kontrollera nätet och försök igen.` No apologies, no "Oops", no exclamation marks.
- Destructive confirmations state the consequence: `Ta bort egenkontrollen? Bilagorna följer med.`

**No emoji. Ever.** Not in UI, not in marketing, not in empty states. Status is carried by a dot, a word, or a hairline — never a glyph with a face.

**Marketing copy** is the same voice, one notch more assertive, and always concrete about the domain:
> **Hela kedjan. Ett system.**
> Från första platsbesök till sista fakturan. Inga dubbelregistreringar, ingen pärm som saknas.

Avoid: "revolutionerande", "AI-drivet" (unless it literally is, then say what it does), "sömlös", "kraftfull", stacked adjectives, exclamation marks, questions as headlines.

**Length rules of thumb.** Button 1–2 words. Table header 1–2 words. Card title ≤ 4 words. Marketing headline ≤ 6 words. Body paragraph ≤ 3 sentences. Tooltip one sentence, no period.

## Visual foundations

The two references pull in the same direction: **Apple** for restraint, optical care and hairline structure; **Polestar** for a nearly monochrome palette, generous emptiness and one hard accent. Kopplas reads as *instrument panel, not dashboard art*.

### Colour

- **Ground is white.** `--bg-page: #ffffff`. Page background is never grey; grey (`--bg-sunken`, `#f5f5f6`) is used *inside* the frame — table zebra-free row hovers, inset panels, sidebar — so the hierarchy reads as depth by tone, not by shadow.
- **Ink is near-black**, `#0d0d0f` (`--n-950`), never `#000` for text. Pure black is reserved for inverse surfaces and the wordmark.
- **The greys are the palette.** 14 steps from `--n-025` to `--n-950`, all near-neutral with a very slight cool cast. Borders live at `--n-100`/`--n-150`; secondary text at `--n-600`; disabled at `--n-300`.
- **One accent: signal yellow** `--signal-400 #ffd21f`. It is voltage. It appears on: the primary marketing CTA, the active-phase marker in the project chain, live/"pågår" indicators, chart emphasis, and text selection. **Budget: under ~5% of any screen's area.** Two signal elements in one viewport is usually one too many. Black text on signal, never white.
- **Semantic hues are muted and functional only** — `--ok-500 #137a43`, `--warn-500 #a86a12`, `--risk-500 #b3261e`, `--info-500 #2f4bd1`. They are used at small sizes: a 6px status dot, a badge with a 50-tint background, a number that has gone the wrong way. Never as a section background, never as a gradient.
- **No gradients** as decoration. The only permitted gradients are functional protection scrims: a bottom-up `rgba(13,13,15,.6) → transparent` over a photograph carrying text, and edge fades on scroll containers.
- **Primary buttons are black**, not coloured. Colour is information; black is action.

### Typography

- **One family: Inter Variable** (`--font-core`), supplied by the client. Weights used: 400 body, 500 for nearly all headings and labels, 600 only for numeric emphasis and the wordmark. **Bold (700+) is not used.**
- **Optical sizing matters.** Inter's `opsz` axis is on: at 30px and above set `font-variation-settings:"opsz" 32` and tighten tracking to `--track-display (-0.03em)`. Big type is tight; small type is loose (`--track-label`, `--track-caps`).
- **Scale**: 11 / 12 / 13 / 14 / **15 (body)** / 17 / 20 / 24 / 30 / 38 / 52 / 72 / 104. Body is 15px in-app, 17px in marketing prose.
- **Line height**: 1.05 display, 1.2 headings, 1.45 body, 1.6 long prose. Measure caps at `--prose-max: 660px`.
- **Numerals**: `font-variant-numeric: tabular-nums` in every table, metric and money field. Proportional elsewhere.
- **Italic** is used for one thing only: a quoted field value or a system-inserted note. Never for emphasis.
- **Mono** (`--font-mono`, system stack) for IDs, project numbers, article numbers, timestamps in logs — `PRJ-2026-0184`.
- **No letter-spaced small caps, no underlines except links, no text shadows.**

### Space and layout

- Spacing is a 2/4-based ramp: 2, 4, 6, 8, 12, 16, 20, 24, 32, 40, 56, 72, 96, 128, 176. In-app rhythm is 8/12/16/24; marketing rhythm is 32/56/96/128.
- **App shell**: 248px sidebar (`--sidebar-w`), 56px topbar (`--topbar-h`), 24px content gutter. Sidebar sits on `--bg-sunken` with a right hairline; topbar is white with a bottom hairline and is `position: sticky`.
- **Marketing**: 1240px max width (`--page-max`), 32px gutters, sections separated by 96–128px of vertical space and, when a boundary is needed, a single full-width hairline — not a colour band.
- Control heights: 28 / 34 / 44px. **44px minimum for anything a gloved thumb touches** in the field views.
- Emptiness is a feature. When in doubt, remove a divider before adding one.

### Borders, cards, elevation

- **Hairlines do the structural work.** 1px `--border-default` (#e4e4e6). Cards are `background: var(--surface-card)` + 1px border + `--radius-card (8px)` and **no shadow at rest**. A card that needs a shadow is probably a floating layer, not a card.
- Shadow is reserved for things that actually float: dropdowns and popovers `--shadow-md`, modals and sheets `--shadow-lg`. Nothing anchored to the page grid gets a shadow.
- **Radii**: 3px chips/tags, **5px controls (`--radius-control`)**, 8px cards, 12px sheets/modals, pill only for status chips and avatars. Nothing is rounder than 12px except pills. No 16px+ "friendly" cards.
- Dividers inside a card are full-bleed hairlines, not inset ones.
- **Transparency and blur** appear in exactly two places: the sticky topbar over scrolled content (`--bg-glass` + `--blur-glass`) and modal scrims (`--bg-scrim`, 48% ink). Nothing else is translucent.

### Motion

- **Fast, short, and only where it explains something.** 140ms for control feedback, 220ms for entering panels, 420ms for a sheet or route change. `--ease-standard cubic-bezier(.2,0,.2,1)` for most things; `--ease-out cubic-bezier(.16,1,.3,1)` for entrances.
- Motion is **opacity + a 4–8px translate**. No scale-up entrances, **no bounce, no spring, no elastic**, no rotation, no staggered card cascades. Marketing reveals are a single 700ms fade-and-rise, once, at `--dur-reveal`.
- Loading is a hairline progress bar or a text state (`Sparar…`), not a spinner soup. Skeletons are flat `--n-050` blocks with no shimmer.
- `prefers-reduced-motion` zeroes every duration (already wired in `tokens/motion.css`).

### Interaction states

- **Hover**: background steps one grey (`--bg-hover`); on dark/primary surfaces the background lightens (`--action-primary-bg-hover`). Text-only and ghost elements drop to 72% opacity. Cards do not lift, do not scale — their border goes to `--border-strong`.
- **Press**: background steps one further (`--bg-active`); no transform, **no shrink**.
- **Focus**: 2px `--focus-ring` (ink) outline with 2px offset — visible, square-ish, never a glow.
- **Selected**: `--bg-selected` + a 2px ink left marker on nav rows; in tables, a full-row `--bg-selected` and a medium-weight first cell.
- **Disabled**: `--text-disabled` foreground, `--bg-inset` background, no opacity trick on the whole node (keeps borders honest).
- Links are ink-coloured with a `--border-strong` underline that darkens on hover. No blue links anywhere.

### Imagery

- Photography is **cool, high-contrast, desaturated but not black-and-white**: switchgear, cable trays, service vans, hands and instruments in real light. Documentary, never staged smiling-with-tablet stock. Slight grain acceptable; heavy filters not.
- Full-bleed images are used sparingly — one per marketing page, usually the hero — and always with either a scrim gradient or text placed outside the image.
- Line-drawing illustration is preferred over 3D or isometric. Diagrams are hairline black on white with a single signal highlight.
- **No illustrations or photos ship with this system** (none were provided). `image-slot` placeholders and grey `--bg-sunken` blocks with a caption stand in — see `assets/README.md`.

## Iconography

- **No icon set was provided.** Kopplas uses **[Lucide](https://lucide.dev)** 0.542.0 — **flagged substitution**. Lucide is the closest match to the intended feel: 24×24 grid, round-cap strokes, geometric, no fills, no colour. The geometry of the 57 icons this system uses is **embedded in `components/core/Icon.jsx`** as inline SVG markup — no CDN, no network, and glyphs survive static capture, print and offline use.
- **Rules**: stroke-only, no fills, no colour of its own. `stroke="currentColor"` always, so icons are ink, secondary grey, or (rarely) a semantic hue. Stroke weight is **1.75 by default** (`strokeWidth` prop): 1.5 at 14px, 1.75 at 16–20px, 2 at 24px+.
- Sizes: 14px inline with small text, **16px default in UI**, 20px in the sidebar and toolbars, 24px in field/mobile touch rows, 32px+ only in empty states.
- Icons are **paired with a label** in navigation and buttons. Icon-only controls exist only in dense toolbars and always carry `aria-label` + tooltip.
- **Unicode as icon**: permitted for a small set of typographic marks — `→` (flow, "next"), `·` (separator), `–` (range), `↑ ↓` (delta direction). Not `✓`, not `★`, not arrows in buttons where a real icon exists.
- **Status is a dot, not a glyph**: a 6px circle in a semantic colour, plus the word. This is the single most repeated pattern in the product.
- The one brand-specific glyph is a **bolt** used as the live/pågår marker and in the favicon-scale mark; it comes from Lucide (`zap`), so it is not a bespoke logo.
- **No emoji, no flags, no coloured icon sets, no duotone.**

### Logo

**None exists.** Wherever a mark belongs, the wordmark is set in plain type: `Kopplas` in Inter 500, `--track-heading`, ink on white or white on ink, optically aligned with a 6px signal-yellow square only in the app's collapsed sidebar. `assets/wordmark.html` shows the two permitted lockups. **Do not draw a logo** — request one from the client.

### Intentional additions

Nothing here derives from a provided component library, so the inventory is the standard set above, plus three domain primitives the product cannot be drawn without:

- **`PhaseChain`** — the five-phase progress spine (prospektering → fakturering). It *is* the product's core metaphor.
- **`StatusDot`** — the dot+word status pattern described under Iconography.
- **`Metric`** — label-over-number KPI block with tabular numerals and optional delta.

## Caveats

1. **Brand name is unconfirmed** (Kopplas chosen from three candidates).
2. **No logo** — wordmark in type only. Not drawn, by policy.
3. **Icons are a flagged substitution** (Lucide from CDN). Swap if the client has a set.
4. **No mono typeface supplied** — system mono stack used.
5. **No photography or illustration supplied** — placeholders only.
6. **Colours, spacing and component behaviour are proposals**, not recreations of an existing product.
